# 001 — Production Readiness Gaps & Scope Lock Rules

**Source of Truth:** `notes/FORENSIC-AUDIT-REPORT.md` & `notes/000-BASELINE-FREEZE.md`  
**Rule:** কোনো Phase ইমপ্লিমেন্ট করার সময় **Scope Lock** ভাঙা যাবে না। নির্দিষ্ট Phase-এর বাইরের কোনো working UI, ডিজাইন টোকেন, রাউট বা ফাংশন পরিবর্তন করা সম্পূর্ণ নিষিদ্ধ।

## 1. Exact Production Gaps Mapped From Forensic Report

| Gap ID | Severity | Exact Verified Defect | Required Production Fix |
| :--- | :--- | :--- | :--- |
| **`FA-001`** | CRITICAL | `requestPasswordReset` ও `requestPasswordResetAction` সরাসরি ব্রাউজারে `token` পাঠায় এবং `PasswordResetForm` স্ক্রিনে প্রিন্ট করে দেয়। | আনঅথেনটিকেটেড প্লেইনটেক্সট টোকেন UI এক্সপোজার সম্পূর্ণ বন্ধ করা; অ্যাডমিন-ইস্যুড রিসেট লিংক/টোকেন বা ভেরিফায়েড ডেলিভারি/CLI (`auth:operator`) ফ্লো চালু করা; ব্রাউজারে কখনো টোকেন রিটার্ন না করা। |
| **`FA-002`** | HIGH | `AdminAccount` রিসেট টোকেন ও `/contact` CSRF/রেট-লিমিট মেমরিতে থাকে; প্রোডাকশনে `ephemeralProductionSecret` ফলব্যাক হয়। | `AdminResetToken` টেবিল (অথবা `admin_id` সাপোর্ট সহ টোকেন স্টোরেজ) PostgreSQL-এ নেওয়া; `/contact` CSRF-কে স্ট্যাটিসলেস HMAC-সাইনড টোকেনে (ইমেজ/রেপ্লিকা সেফ) ও রেট-লিমিট DB/অডিট-ব্যাকড করা; `CONTACT_SECRET_KEY` `env-schema.ts`-এ যোগ করা। |
| **`FA-003`** | HIGH | `MessageReaderView` `<iframe sandbox>` ব্যবহার না করে প্যারেন্ট DOM-এ `dangerouslySetInnerHTML` চালায়; `getMessageDetailForUser` `htmlBody` ইনলাইন পাঠায়। | রিডারে `<iframe sandbox>` চালু করে সরাসরি `/api/messages/html/[messageUuid]` সোর্স লোড করানো (`CSP: SAFE_HTML_CSP_POLICY` সহ) এবং মূল অ্যাপ DOM থেকে `dangerouslySetInnerHTML` ইমেইল ইনজেকশন সরানো। |
| **`FA-004`** | HIGH | Docker/Coolify-তে Maildir ইনজেশন ওয়ার্কার কন্টেইনার, রিটেনশন ক্রন এবং প্রোডাকশন ইমেজে `ingest.ts`/`tsx` নেই। | `Dockerfile`-এ ওয়ার্কার স্ক্রিপ্ট ও রানটাইম ডিপেন্ডেন্সি যুক্ত করা; `docker-compose.yml`-এ আলাদা `worker` সার্ভিস (ইনজেশন + পর্যায়ক্রমিক রিটেনশন পার্জ) ও Postfix/Dovecot ইন্টিগ্রেশন নির্দেশিকা/রোল কনফিগার করা। |
| **`FA-005`** | HIGH | `runUpdatePreflight` কন্টেইনারে অনুপস্থিত `systemd`/`nginx`/`postfix`/`vmail` খোঁজে; `restore.sh` ও `env-schema.ts`-এ পুরনো `vibmail`/`mailstack.local` ডিফল্ট। | `env-schema.ts` ডিফল্ট `readbox.local`/`/run/readbox`-এ আপডেট করা; `restore.sh` আধুনিকায়ন; `updates/service.ts`-এ কন্টেইনার/Coolify রানটাইম ডিটেকশন দিয়ে ভুল systemd ব্লকার সরানো। |
| **`FA-006`** | HIGH | `createManagedUser`/`updateManagedUser` নতুন `UserAccessPolicy`-তে স্কিমা ডিফল্ট সেভ করে গ্লোবাল `UserControlSettings` ওভাররাইট করে; `runRetentionPurge` কোথাও কল করা হয় না। | প্যার-ইউজার ওভাররাইড মডেল ও `resolveEffectiveUserPolicy`-তে explicit override vs inherit আলাদা করা; `runRetentionPurge` `/vcon/operations` UI-তে এবং ব্যাকগ্রাউন্ড ওয়ার্কার লুপে যুক্ত করা; `updateMany` ব্যাচ পার্জ ব্যবহার। |
| **`FA-007`** | MEDIUM | `getPrismaClient()`, `/sign-up`, `user-control-policy`, `settings/service` প্রোডাকশনে DB ব্যর্থ হলে নীরবে মক/ডেমো ডেটা দেয়। | `NODE_ENV === "production"`-এ মক প্রিজমা ও ডেমো ফলব্যাক নিষিদ্ধ করা; স্পষ্ট `Service Unavailable` (503/Error Banner) দেখানো। |
| **`FA-008`** | MEDIUM | `/contact` ইনকোয়ারি `audit_logs`-এ সেভ হয় কিন্তু `/vcon`-এ দেখার কোনো UI নেই (`listContactSubmissions` অব্যবহৃত)। | `/vcon/inquiries` (বা `/vcon/audit` সাব-ভিউ) তৈরি করে অ্যাডমিনদের কন্টাক্ট ইনকোয়ারি লিস্ট ও ফিল্টার করার ব্যবস্থা। |
| **`FA-009`** | MEDIUM | `admin_accounts` অডিটে `targetType` ৩ রকম (`admin_account`, `user`, `admin`); মেসেজ API রুটগুলোতে `authSource` নেই; অ্যাডমিনের ফোন ফিল্ড সেভ হয় না। | `targetType: "admin"` ইউনিফাই করা বা ফিল্টারে সব অ্যাডমিন টাইপ ধরা; `/api/messages/*` ও `/users/*`-এ `authSource: user.authSource` পাস করা; `admin_table` প্রোফাইলে প্রযোজ্য না হলে ফোন ফিল্ড হাইড/রিড-অনলি করা। |
| **`FA-010`** | MEDIUM | `tryProvisionStarterMailbox` এর ফলব্যাক ভাঙা `maildirRelativePath` ও `mailserver` অনুপস্থিত রো তৈরি করে। | ফলব্যাক সরিয়ে কেবল প্রকৃত `provisionMailbox()` ব্যবহার করা অথবা প্রোডাকশনে কন্ট্র্যাক্ট ভেঙে রো তৈরি না করে নিরাপদে স্কিপ/লগ করা। |
| **`FA-011`** | MEDIUM | `PublicSiteFooter` `sourceCodeUrl` দেখায় না; `manifest.ts` সিঙ্ক ক্যাশ পড়ে; `/health/ready` `mailServices.connected` বাদ দেয়; `SERVER_IP=127.0.0.1` IP চেক এড়ায়; `USE_X_ACCEL_REDIRECT` env-schema-তে নেই; `trusted-operations.ts` স্টাব। | ফুটারে `sourceCodeUrl` রেন্ডার, `manifest.ts`-এ async `getSiteSettings()`, `/health/ready`-তে ওয়ার্কার হেলথ/strictness অপশন, `env-schema.ts`-এ `USE_X_ACCEL_REDIRECT` ও প্রকৃত টেবিল ভেরিফিকেশন ফিক্স। |

## 2. Phase-Wise Scope Lock Matrix (Non-Negotiable Boundaries)

প্রতিটি Phase শুরু ও শেষ হওয়ার সময় কেবল নির্ধারিত ফাইলগুলোই পরিবর্তিত হতে পারবে:

| Phase | Scope Lock — অনুমোদিত ফাইল/মডিউল | Strictly Untouched (হাত দেওয়া নিষেধ) |
| :--- | :--- | :--- |
| **Phase 1: Auth, Reset & Security Integrity** | `prisma/schema.prisma` (only `AdminResetToken` or `adminId` FK + migration), `src/core/auth/password-reset.ts`, `src/app/reset-password/*`, `src/components/auth/password-reset-form.tsx`, `src/core/contact/service.ts`, `src/app/api/contact/*`, `src/config/env-schema.ts`, `src/core/auth/credentials.ts`, `src/core/accounts/user-profile.ts`, `src/app/api/messages/{html,attachment}/**`, `src/app/(workspace)/users/**`, auth tests. | Public landing UI (`/`), `/users` inbox styling, `/vcon/domains`, `/vcon/operations`, `Dockerfile`, `docker-compose.yml`. |
| **Phase 2: Sandboxed Reader & Policy Inheritance** | `src/components/users/message-reader-view.tsx`, `src/core/messages/service.ts` (`getMessageDetailForUser`, `buildSanitizedHtmlDocument`), `src/app/api/messages/html/[messageUuid]/route.ts`, `prisma/schema.prisma` (`UserAccessPolicy` nullable/override flags if needed), `src/core/accounts/users.ts`, `src/core/accounts/policy.ts`, `src/core/accounts/user-control-policy.ts`, related tests. | Auth/login pages, `/vcon/settings`, `/vcon/system-update`, public site, `Dockerfile`, `docker-compose.yml`. |
| **Phase 3: Retention Purge, Mail Contract, DNS & Branding Polish** | `src/core/operations/service.ts`, `src/core/messages/service.ts` (batch purge), `src/app/(workspace)/vcon/operations/actions.ts`, `src/components/vcon/operations-console.tsx`, `src/core/auth/sign-up.ts` (`tryProvisionStarterMailbox`), `src/components/public/public-site-footer.tsx`, `src/app/manifest.ts`, `src/core/dns/resolver.ts`, `src/core/setup/trusted-operations.ts`, related tests. | Auth reset flow, `/users/inbox` iframe reader, `Dockerfile`, `docker-compose.yml`. |

| **Phase 5: Admin Inquiries Console & Admin Profile Parity** | `src/app/(workspace)/vcon/inquiries/page.tsx` (new), `src/components/vcon/inquiries-console.tsx` (new), `src/components/layout/app-shell.tsx` (1 nav link only), `src/components/users/user-settings-view.tsx` (`admin_table` phone visibility), `src/core/accounts/user-profile.ts`, related tests. | Core auth logic, reader sandbox, `Dockerfile`, `docker-compose.yml`. |
| **Phase 6: Docker, Coolify, Worker Runtime, Updater & Health Gate** | `Dockerfile`, `docker-compose.yml`, `entrypoint.sh`, `.env.example`, `src/workers/ingestion.ts`, `scripts/mail/ingest.ts`, `scripts/ops/restore.sh`, `scripts/updater/update_worker.py`, `src/core/updates/service.ts`, `src/config/env-schema.ts` (legacy defaults), `src/core/health/snapshot.ts`, `tests/compatibility/*`. | All `/users` UI components, public pages, auth business logic. |
